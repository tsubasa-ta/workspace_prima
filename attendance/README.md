# Prima 勤怠管理

社員・スタッフが Web ページにログインして打刻し、記録を Google スプレッドシートに残す勤怠システムです。
Google Apps Script（GAS）で動くため、サーバー代はかかりません。

## できること

- **ログイン**：名前を選んで PIN を入力します（Google アカウントは不要）
- **打刻**：出勤・退勤の2つです。その時点で押せるボタンだけが表示されます
- **休憩**：退勤を押すと休憩時間（なし・15分〜120分）を選ぶ画面が出ます。出勤からの経過時間に応じて、法定の目安（6時間超は45分、8時間超は60分）が最初から選ばれています
- **メモ**：遅刻の理由や直行直帰などを打刻に添えられます
- **自分の記録**：今日の打刻と、今月の出勤・退勤・休憩・実働時間を表示します
- **管理者画面**：全員の本日の出勤状況（未出勤・勤務中・休憩中・退勤済）を表示します
- **有給休暇・休日出勤の申請**：有給（1日・午前半休・午後半休）と休日出勤を勤怠ページから申請できます。社長（承認者）が承認・却下すると、結果が本人の画面に表示されます
- **有給の残日数**：付与日数から承認済みの取得日数を引いた残日数を表示します。残日数が足りない申請はできません
- **通知メール**：メールアドレスを登録した人には、申請が来たとき（承認者）と、承認・却下されたとき（申請した本人）にメールが届きます
- **月次集計**：スプレッドシートのメニューから「個人別合計」と「日別明細」のシートを作ります。給与計算用に、実働時間を小数（例：8.5時間）でも出します。有給の取得日数と休日出勤の日数も集計します
- **安全対策**：打刻時刻はサーバーの時刻を使うため、端末の時計を変えても不正打刻はできません。PIN は暗号化（ハッシュ化）して保存し、5回まちがえると15分間ロックします

## 設置手順（15分ほど）

### 1. スプレッドシートを作る

1. Google ドライブで新しいスプレッドシートを作ります（名前の例：「Prima 勤怠」）
2. メニュー **拡張機能 → Apps Script** を開きます

### 2. コードを貼り付ける

1. 最初からある `コード.gs` の中身をすべて消し、このフォルダの **`Code.gs`** の内容を貼り付けます
2. 左の「ファイル」の **＋ → スクリプト** を選び、名前を **`Requests`** にして、**`Requests.gs`** の内容を貼り付けます
3. 左の「ファイル」の **＋ → HTML** を選び、名前を **`index`** にして、**`index.html`** の内容を貼り付けます
4. 💾（保存）を押します

> 下の「GitHub から自動で反映する」を設定すると、2回目以降はこの貼り付け作業が不要になります。

### 3. 初期設定

1. スプレッドシートの画面に戻り、ページを再読み込みします
2. メニューに **「勤怠」** が出るので、**勤怠 → 初期設定（最初に1回）** を実行します
   - 初回は権限の確認が出ます。「許可」を選んでください（「このアプリは確認されていません」と出たら「詳細 → 安全ではないページに移動」を選びます。自分で作ったスクリプトなので問題ありません）
3. 「スタッフ」「打刻ログ」「申請」のシートができます

### 4. スタッフを登録する

「スタッフ」シートに1人1行で入力します。

| ID | 名前 | 区分 | PIN | 管理者 | 有効 | 承認者 | 有給付与日数 | 付与日 | メール |
|----|------|------|-----|--------|------|--------|------|------|------|
| 001 | 岡山 太郎 | 社員 | 4821 | ☑ | ☑ | ☐ | 10 | 2026-04-01 | |
| 002 | 山田 花子 | スタッフ | 7305 | ☐ | ☑ | ☐ | 7 | 2026-10-01 | |
| 003 | 社長 | 社員 | 9152 | ☐ | ☑ | ☑ | | | boss@example.com |

- **ID**：重複しない番号です。あとから変えないでください
- **PIN**：4〜6桁の数字がおすすめです。最初のログインで自動的に暗号化され、`sha256:…` という文字列に変わります
  - PIN を変えたいときは、その欄に新しい数字を入力し直します
- **管理者**：チェックを付けた人は、全員の出勤状況を見られます
- **有効**：退職した人はチェックを外します。ログインできなくなりますが、過去の記録は残ります
- **承認者**：チェックを付けた人（社長）が、有給休暇・休日出勤の申請を承認・却下できます。`TRUE` と入力してもかまいません
- **有給付与日数**：今の付与期間に使える有給の日数です（前年からの繰越分を含めた合計）。空欄の人は残日数を管理しません
- **付与日**：今の付与期間が始まった日です。この日以降に承認された有給を「取得済み」として数えます
  - 毎年の付与日が来たら、**有給付与日数**（新しい付与日数＋繰越日数）と**付与日**を書き換えてください
- **メール**：入力すると通知メールが届きます。空欄なら届きません

> 例として入っている「001 校舎長（例）／PIN 1234」は、自分の情報に書き換えてください。

### 5. Web ページとして公開する

1. Apps Script の画面で、右上の **デプロイ → 新しいデプロイ** を選びます
2. 歯車アイコンから種類に **「ウェブアプリ」** を選びます
3. 次のように設定します
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. **デプロイ** を押すと、`https://script.google.com/macros/s/…/exec` という URL が表示されます
5. この URL をスタッフに共有します（スマホのホーム画面に追加しておくと便利です）

> 「アクセスできるユーザー：全員」でも、記録できるのは PIN を知っている登録スタッフだけです。
> スプレッドシート自体は共有しないでください。

## 使い方

### スタッフ

1. URL を開き、名前を選んで PIN を入力します（ログイン状態は6時間保たれます）
2. 出勤時に「出勤」を押します
3. 帰るときに「退勤」を押し、休憩時間を選んで「退勤する」を押します

### 管理者（校舎長）

- **月の集計**：スプレッドシートのメニュー **勤怠 → 月次集計を作成** を選び、`2026-11` のように月を入力します。`集計_2026-11` シートができます
- **打刻の修正**：「打刻ログ」シートを直接編集します
  - 押し忘れた分は、行を追加して **日時・スタッフID・種別** を入力します（日付・名前は空欄でもかまいません。集計は「日時」列から計算します）
  - 種別は `出勤` か `退勤` を正確に入力してください
  - 休憩時間は、退勤の行の **G列「休憩(分)」** に分単位で入力します（例：60）
- **退勤漏れ**：退勤を押し忘れた日は、集計に「退勤漏れ」と表示されます。修正するまでその日の実働は正しく計算されません

### 承認者（社長）

1. 勤怠ページにログインすると、上のほうに **「承認待ちの申請」** が表示されます
2. 必要ならコメントを入れて、**承認** か **却下** を押します
3. 処理した申請は「最近処理した申請」から確認できます。すべての申請は「申請」シートに残ります

> 承認者も「スタッフ」シートに1行登録し、PIN を設定してください。管理者（校舎長）は承認待ちの一覧を見られますが、承認・却下はできません。

## GitHub から自動で反映する

GitHub の `main` ブランチで `attendance/` のコードが更新されると、GitHub Actions（`.github/workflows/deploy-attendance.yml`）が
Apps Script にコードを送り、公開中のウェブアプリを新しいバージョンに更新します。URL は変わりません。

最初に一度だけ、次の設定が必要です（20分ほど）。

### 1. Apps Script API をオンにする

https://script.google.com/home/usersettings を開き、**「Google Apps Script API」をオン** にします。

### 2. パソコンで Google にログインし、認証ファイルを作る

Node.js が入っているパソコンで、ターミナル（Windows は PowerShell）を開いて実行します。

```bash
npx @google/clasp@2.4.2 login
```

ブラウザが開くので、勤怠のスプレッドシートを作った Google アカウントでログインし、「許可」を押します。
「Authorization successful.」と出たら完了です。ホームフォルダに **`.clasprc.json`** というファイルができます。

- Windows：`C:\Users\（ユーザー名）\.clasprc.json`
- Mac：`/Users/（ユーザー名）/.clasprc.json`

> このファイルは Google アカウントを操作できる鍵です。人に渡したり、リポジトリにコミットしたりしないでください。

### 3. GitHub に Secrets（秘密の設定値）を登録する

GitHub のリポジトリで **Settings → Secrets and variables → Actions → New repository secret** を開き、次の3つを登録します。

| 名前 | 値 | 調べ方 |
|------|-----|--------|
| `CLASPRC_JSON` | `.clasprc.json` の中身すべて | メモ帳などで開いて全文コピー |
| `SCRIPT_ID` | スクリプト ID | Apps Script の ⚙（プロジェクトの設定）→「スクリプト ID」 |
| `DEPLOYMENT_ID` | デプロイ ID | Apps Script の **デプロイ → デプロイを管理** → 公開中のデプロイの「デプロイ ID」 |

### 4. 動かしてみる

- `main` ブランチの `attendance/` が更新されると自動で動きます
- 手動で動かすときは、GitHub の **Actions → 勤怠システムを Apps Script に反映 → Run workflow** を押します
- 緑のチェックが付けば反映完了です。赤い × の場合は、そのジョブを開くとエラーの内容がわかります

### 5. 新しい権限が必要になったとき

メール通知のように、Google の新しい権限を使う機能が追加されたときは、自動反映のあとに一度だけ
Apps Script の画面で関数 `setup` を選んで **▶実行** し、権限を「許可」してください。
許可するまで、ウェブアプリはエラーになります。

> 自動反映を設定したあとは、Apps Script の画面で直接コードを直さないでください。次の自動反映で GitHub の内容に上書きされます。

## コードを手で更新するとき

自動反映を使わない場合は、Apps Script でコードを貼り替えたあとに **デプロイ → デプロイを管理 → ✏（編集）→ バージョン：新バージョン → デプロイ** を実行してください。URL は変わりません。

## 注意事項

- 日付をまたぐ勤務（夜勤など）には対応していません。0時を過ぎると翌日として扱います
- 打刻は1日に何回でもできます（中抜け後の再出勤もできます）
